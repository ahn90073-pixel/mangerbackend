# Backend إدارة Mange

واجهة API للوحة إدارة المتاجر، مبنية باستخدام **Hono وCloudflare Workers وNeon PostgreSQL**. تتطلب جميع مسارات الإدارة مصادقة Bearer؛ والاستثناءات العامة هي `GET /health` و`POST /api/admin/auth/login` و`POST /api/admin/auth/google` فقط.

## الأدوار ونطاق البيانات

- **`super_admin`**: يرى جميع التجار والطلبات، ويمكنه إدارة الموظفين وتعيين محافظة للتاجر ومراجعة المنتجات والعمولات والسدادات وسجل التدقيق.
- **`employee`**: يرى التجار والطلبات التابعين للمحافظات المسندة إلى حسابه، ويمكنه تعديل حالة تاجر أو تحديث طلب داخل هذه المحافظات. لا يصل إلى مراجعة المنتجات أو العمولات أو السدادات أو سجل التدقيق أو إدارة الموظفين.
- يطبّق الخادم النطاق على استعلامات القراءة والتحديث؛ إخفاء الروابط في React ليس حاجز الصلاحيات.
- يعتمد نطاق الطلب على **محافظة التاجر** (`public.companies.governorate`) لا على محافظة عنوان الشحن. لذلك يرى الموظف طلبات تجار محافظاته حتى إن كان عنوان تسليم أحد الطلبات في محافظة أخرى.
- الشركات القديمة تبدأ بمحافظة غير محددة ولا تظهر للموظفين إلى أن يعيّن الأدمن العام المحافظة من صفحة تفاصيل التاجر. لا تُجرى تعبئة تلقائية قد تنسب تاجرًا إلى محافظة خاطئة.

## تشغيل الترحيلات والحساب الأول

يجب تطبيق ترحيلات Tager `0001` إلى `0004` على Neon أولًا، ثم ترحيلات لوحة الإدارة بهذا الترتيب:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f migrations/0001_admin_platform.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f migrations/0002_admin_auth_governorates.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f migrations/0003_firebase_google_admin_auth.sql
```

الترحيلات إضافية وقابلة لإعادة التشغيل؛ تنشئ `public.admin_users`، وتضيف حقول صلاحيات الإدارة ومصادقة Firebase، وتحجز ثلاثة مقاعد للأدمن، وتحدث جداول مراجعة المنتجات. لا تحذف مستخدمين أو طلبات أو بيانات أعمال.

### إعداد تسجيل Google للأدمن

1. فعّل **Google** في Firebase Console ضمن Authentication > Sign-in method، وأضف نطاق الواجهة المنشورة إلى Authorized domains.
2. أضف إعدادات Firebase Web App في بيئة بناء الواجهة (`VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`). هذه إعدادات عميل عامة؛ قيّد Firebase API key بنطاقات التطبيق في Google Cloud.
3. أضف إلى أسرار/متغيرات Cloudflare Worker `FIREBASE_WEB_API_KEY` و`ADMIN_GOOGLE_EMAILS`، إضافة إلى `DATABASE_URL` و`ADMIN_JWT_SECRET` الموجودين مسبقًا. قيمة `ADMIN_GOOGLE_EMAILS` قائمة مفصولة بفواصل من عناوين `@gmail.com` المعتمدة، وبحد أقصى **ثلاثة عناوين مختلفة**.
4. أدرج عناوين الأدمن المسموح بها قبل النشر. الترحيل يحافظ على أول ثلاثة حسابات `super_admin` موجودة بحجز مقاعد لها. عند إزالة عنوان من القائمة، تُمنع جلساته ويُعاد استخدام المقعد لحساب معتمد آخر؛ سجل المستخدم القديم في Neon لا يُحذف.

تتحقق الخدمة من Firebase ID token عبر Firebase Identity Toolkit، ولا تثق بعنوان بريد أو دور يرسله المتصفح. يقتصر مسار كلمة المرور على الموظفين، وتظل صلاحيات الموظفين ومحافظاتهم كما كانت. لا يمكن تحويل بريد موظف إلى أدمن تلقائيًا؛ يجب أن يكون Gmail معتمدًا وحسابه بدور `super_admin`.

لا حاجة لإنشاء حساب أدمن بكلمة مرور يدويًا. بعد تطبيق الترحيل وإعداد `ADMIN_GOOGLE_EMAILS` وFirebase، يُنشأ سجل أول أدمن تلقائيًا في Neon عند أول دخول ناجح بأحد عناوين Gmail المعتمدة. الأدمن العام الحالي يُربط بعنوان Firebase عند أول دخول Google إذا كان عنوانه ضمن القائمة. إنشاء الموظفين يظل من صفحة «إدارة الموظفين» بكلمة مرور ومحافظة أو أكثر.

## إعداد الأسرار

أنشئ قيمة عشوائية مستقلة لتوقيع الجلسات، ولا تستخدم كلمة مرور الأدمن أو قيمة `DATABASE_URL` لهذا الغرض. مثال للتوليد:

```bash
openssl rand -base64 48
```

أضف القيمة باسم `ADMIN_JWT_SECRET`، واحتفظ أيضًا بـ`DATABASE_URL`, `FIREBASE_WEB_API_KEY`, و`ADMIN_GOOGLE_EMAILS` في أسرار/متغيرات Cloudflare Worker. عند استخدام Workflow النشر اليدوي، أضف أسرار النشر المطلوبة إلى GitHub Actions secrets. لا تُسجل أي أسرار في Git. مدة رمز الدخول 8 ساعات، ويتحقق الخادم من حالة الحساب والدور والمحافظات من Neon في كل طلب. إيقاف الموظف يرفع `token_version` فيبطل جلساته القائمة، وتغيير قائمة أدمن Google يقيّد جلسات الأدمن فورًا.

محليًا، املأ `.dev.vars` ثم شغّل:

```bash
npm run dev
```

لا يتصل إعداد branch previews بقاعدة الإنتاج ولا يملك سر توقيع؛ لذلك لا تسجل الدخول إلى preview إلا بعد تجهيز أسرار اختبار مستقلة.

## مسارات API

جميع المسارات التالية تبدأ بـ`/api/admin`، وتحتاج `Authorization: Bearer <token>` ما عدا تسجيل الدخول.

| المسار | الصلاحية | الوظيفة |
|---|---|---|
| `POST /auth/login` | عام | دخول الموظفين بكلمة المرور؛ حسابات الأدمن تستخدم Google |
| `POST /auth/google` | عام | يتحقق من Firebase/Google، ويسجل حساب الأدمن المعتمد (حتى 3) في Neon ويصدر رمزًا محدودًا بثماني ساعات |
| `GET /auth/me` | أي مستخدم مسجل | ملف الحساب والدور والمحافظات |
| `POST /auth/logout` | أي مستخدم مسجل | إنهاء جلسة الواجهة؛ يحذف العميل الرمز. ينتهي الرمز أيضًا بعد 8 ساعات |
| `GET /dashboard` | أدمن أو موظف | المؤشرات والطلبات ضمن نطاق المستخدم |
| `GET /vendors` و`GET /vendors/:id` | أدمن أو موظف | قائمة وتفاصيل التجار؛ الموظف لا يتجاوز محافظاته ولا يرى حقول المالية |
| `PATCH /vendors/:id/status` | أدمن أو موظف ضمن النطاق | تحديث حالة تاجر مصرح به |
| `PATCH /vendors/:id/governorate` | أدمن عام | تعيين أو تغيير محافظة التاجر |
| `GET /orders` و`GET /orders/:vendorId/:orderId` | أدمن أو موظف ضمن النطاق | قائمة الطلبات وتفاصيلها |
| `PATCH /orders/:vendorId/:orderId` | أدمن أو موظف ضمن النطاق | تحديث حالة الطلب والشحنة ورسومها |
| `GET /employees` | أدمن عام | قائمة الموظفين ومحافظاتهم وحالة الحساب |
| `POST /employees` | أدمن عام | إنشاء موظف بالاسم والبريد وكلمة المرور ومحافظة واحدة على الأقل |
| `PATCH /employees/:id/status` | أدمن عام | تفعيل أو إيقاف موظف وإبطال جلساته |
| `GET /products*`, `PATCH /products*`, `DELETE /products*` | أدمن عام | مراجعة المنتجات وإدارتها |
| `GET /settlements*`, `POST /settlements`, `PATCH /settlements*` | أدمن عام | إدارة السدادات المالية |
| `GET /audit-logs` | أدمن عام | قراءة سجل التدقيق |

كلمة مرور الموظف يجب أن تكون 12 محرفًا على الأقل. تُطابق المحافظات قائمة مصر المعتمدة، ويُرفض إنشاء موظف من دون محافظة واحدة على الأقل أو تمرير اسم محافظة غير معروف.

## التحقق والنشر

```bash
npm ci
npm test
npm run lint
npm run build
```

`build` يستخدم `wrangler deploy --dry-run` ولا ينشر. Workflow النشر في GitHub يدوي فقط. إذا فُعّل خيار تطبيق الترحيلات فإنه يطبق `0001_admin_platform.sql` ثم `0002_admin_auth_governorates.sql` قبل النشر؛ راجع نسخة قاعدة البيانات وخطة الترحيل قبل تشغيله على الإنتاج.
